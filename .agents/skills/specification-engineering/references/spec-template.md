## Типовые критерии готовности
- Компонент работает в чистом .NET-сервисе, подключающем только эту возможность (если независимость — требование).
- Для каждого отказа определены ответственный за retry, условия, budget/max, диагностика и финальный результат.
- Понятны имена настроек, значения по умолчанию, precedence, секреты, validation и поведение при неправильной конфигурации.
- Cancellation, завершение и readiness/liveness проверяемы.
- Есть план реального интеграционного теста (Testcontainers или аналог, если уместно), а не только регистрации DI.
- Версионированные контракты имеют правила эволюции, тесты совместимости и политику breaking changes.
- Ошибки дают достаточно контекста без утечки секретов и персональных данных.
