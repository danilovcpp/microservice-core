# Дорожная карта — предварительный план

| Этап | Результат | Условие перехода |
|---|---|---|
| 0. Discovery | 2 характерных сервиса, требования и ограничения, открытые вопросы | Пользователь подтверждает цели и ограничения |
| 1. Research | Обоснованные альтернативы build-vs-buy, кандидаты на стек | Выбраны технологические направления |
| 2. Design | Модули, зависимости, API-эскизы, потоки, proposed ADR | Пользователь утверждает ключевые ADR |
| 3. Challenge | Внешний архитектурный review, отказоустойчивость, упрощение | Закрыты блокирующие замечания |
| 4. Specification | RFC по компонентам, acceptance tests, API compatibility, roadmap | Пользователь утверждает спецификацию |
| 5. Implementation — **не разрешён** | Тонкий вертикальный срез, затем модули и примеры | Требуется отдельная просьба пользователя |

## Возможные вертикальные срезы реализации — обсудить позже
1. Тонкие host defaults, диагностика и один реальный микросервис.
2. Простейшая application-операция и обработчик с тестовым каркасом.
3. Kafka producer/consumer с выбранными реальными failure semantics.
4. Outbox/inbox и Postgres-согласованность, **только если требуется**.
5. gRPC server/client, health, auth и resilience.
6. Опциональные пакеты, шаблон создания сервиса, совместимость и release automation.

Это не утверждённая очередность. Каждая фаза должна иметь работающий сценарий и проверяемые acceptance criteria; не реализовывать все компоненты одним огромным коммитом.
