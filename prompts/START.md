# Первая сессия — начать проектирование

Выступай как мой независимый Principal .NET Platform Architect с опытом production-платформ, DDD, Kafka, gRPC, PostgreSQL, observability и developer experience. Прочитай `AGENTS.md`, `docs/PROJECT_STATE.md`, `docs/00-vision.md`, затем используй skill `$discovery-interview`.

Я хочу архитектурно спроектировать набор переиспользуемых компонентов для .NET-микросервисов и удобный механизм создания нового сервиса. Меня интересуют Kafka publisher/consumer, CQRS/handlers, базовые DDD-абстракции, gRPC, PostgreSQL, Serilog, диагностика и всё необходимое для надежной эксплуатации. Пример `Platform.AddKafka().AddGrpc().AddPostgres()` — демонстрация желаемого developer experience, а не предписанный API.

**Твоя задача сейчас — НЕ писать код.** Сначала разберись, какую проблему мы решаем и нужно ли нам строить собственную Platform в предлагаемом виде. Предлагай решения, которых я не назвал. Изучи практики и существующие проекты, когда это будет уместно; сопоставь build-vs-buy, простоту и операционную надежность. Разделяй «платформенные библиотеки», «шаблон нового сервиса», «инфраструктуру», «локальную оркестрацию», «DDD building blocks» и «готовые опции ASP.NET Core».

В первой реакции:
1. Кратко сформулируй моё намерение и 3–5 наиболее важных неизвестных, которые определят архитектуру.
2. Дай начальную карту возможных компонентов, выделив MUST / LATER / MAYBE и оговорив, что это только гипотеза.
3. Задай **первую партию из 3–5 сильных вопросов**, которые реально помогут принять решения; не присылай все вопросы сразу. Предложи свои разумные дефолты.
4. Сохрани важные наблюдения и вопросы в `docs/`, обнови `docs/PROJECT_STATE.md`.
5. Остановись в диалоге в ожидании моих ответов, не переходя к реализации.

На последующих этапах, когда информации достаточно, сам предлагай исследовать конкретный вопрос, создавай сравнения альтернатив, RFC/ADR и подробные спецификации — но фиксируй спорные решения только после моего согласования.
