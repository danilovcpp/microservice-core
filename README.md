# Codex Principal .NET Platform Architect

Готовый комплект инструкций для **архитектурного проектирования платформы .NET-микросервисов**. Это не реализация Platform и не сгенерированный framework. Задача набора — превратить расплывчатую идею в проверенные и согласованные архитектурные решения, а затем в качественное ТЗ.

## Установка

1. Распакуйте архив **с сохранением скрытой папки `.agents`** непосредственно в корень нового Git-репозитория. Файл `AGENTS.md` должен оказаться в корне.
2. Откройте **корень** этого репозитория как workspace в Codex.
3. Создайте новый чат и отправьте содержимое [`prompts/START.md`](prompts/START.md) или напишите: `Прочитай prompts/START.md и начни архитектурную сессию.`
4. Отвечайте на вопросы архитектора итерациями. В следующем чате используйте [`prompts/CONTINUE.md`](prompts/CONTINUE.md).
5. Вносите в Git изменения в `docs/` между сессиями: это долговременная память об архитектуре.

Не требуется «регистрировать агента» как системный prompt: Codex читает `AGENTS.md` как инструкции репозитория и может обнаружить repo-local skills в `.agents/skills/`.

## Что находится в комплекте

- `AGENTS.md`: роль, ограничения, характер общения, правила принятия решений и работы с памятью.
- `.agents/skills/`: пять отдельных навыков — интервью, исследование, дизайн, review, спецификация.
- `prompts/`: старт с нуля, продолжение, архитектурная критика.
- `docs/`: vision, список вопросов, результаты исследований, ADR, архитектура, критерии готовности, дорожная карта и текущий статус.

## Принцип работы

**Discover → Research → Design → Challenge → Specify → (после отдельного разрешения) Implement.**

В начале агент не должен автоматически создавать `.sln`, библиотеки или код. Он обязан сначала выяснить контекст и предложить решение о том, **что вообще имеет смысл писать самим**. Он задаёт по нескольку вопросов, а не присылает единовременно анкету из десятков пунктов. Договорённости фиксируются в файлах.

## Примечания

- Название `Platform` и пример fluent API — временные идеи, не обязательный контракт.
- Целевая версия .NET, способ хостинга, Kafka-клиент, persistence layer и пакеты должны быть **проверены и согласованы**, а не предрешены этим набором.
- Для фактического исследования актуальных библиотек и лицензий нужен доступ Codex к документации/Интернету. Без него агент обязан помечать данные как непроверенные.
- После готовности ТЗ лучше запускать реализацию по отдельным фазам; данный комплект сознательно ставит человеческое согласование архитектуры впереди написания кода.
